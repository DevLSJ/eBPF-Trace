# SupplyGuard — 프론트엔드 목업

정적 HTML · 바닐라 JS · 외부 라이브러리 없음. React 대시보드(`frontend/`)와 같은 데이터 스키마 · 디자인 토큰을 쓴다.
**React 가 기준이고 목업은 결정 확인용이다** [2026-10-15]. 화면 변경은 목업에서 먼저 보이고 확정한 뒤 React 에 옮긴다.
두 시나리오(설치 검사 · 런타임 감시)를 같은 비중으로 다룬다.

## 열기

| 방법 | 명령 |
| --- | --- |
| 파일로 바로 | `mock/index.html` 을 브라우저로 연다 (file:// 로 동작) |
| 로컬 서버 | `make mock` → http://127.0.0.1:8766/ (8765 는 다른 프로젝트 목업이 쓰므로 8766) |
| 실제 백엔드에 붙여서 | `make backend` (또는 `make dev`) 로 mock 소스 백엔드를 :8000 에 띄운 뒤 데모 제어 → **데이터 소스: 실제 백엔드 → 연결**. 또는 URL 에 `?source=live&api=http://127.0.0.1:8000` |

키보드 `?` 또는 상단 **? 안내** → 사용 흐름 안내. 상단 **데모 제어**(CLI 대역) → 데이터 소스 전환 · **설치 검사 실행(정상 pip requests / 악성 pip ./reqeusts / 경고 npm tiny-git-dep)** · **런타임 공격 지금 실행** · 자동 공격 주기(기본 끔) · 격리 모드(dry-run) 전환 · 연결 끊김 재현 · 이벤트 속도.

### 주소 옵션 (목업 전용)

| 옵션 | 뜻 |
| --- | --- |
| `?fresh=1` | 빈 서버 — 설치 세션 · 감사 기록 · 건 · 차단 목록 없이 시작(빈 상태 시연) |
| `?source=live&api=<주소>` | 실제 백엔드에 붙는다(쿠키 로그인). 모든 화면이 실제 API 를 부르고, 백엔드에 없는 경로만 「백엔드 미지원」 [10/21] |
| `#/<화면>?id=<항목>` | 상세 시트가 열린 상태(설치 검사 · 이벤트 · 감사 로그 · 정책). **주소에는 링크용 값(id · proposal · tab · view · node)만** — 목록 필터는 화면 상태라 새로고침하면 기본값. 옛 주소로 들어온 필터는 한 번 적용하고 주소에서 지운다 [10/21b] |
| `#/policies?proposal=<id>` · `?id=__blocklist__` | 정책 › 제안 미리보기 · 차단 목록 |
| `#/audit?view=changes` | 감사 로그 › 판정 · 변경 이력(옛 `view=history` 도 읽는다) |
| `#/topology?node=c:<이름>` | 그 컨테이너 노드를 고른 상태(건이 있으면 판정 카드). 파일 · 도메인 노드는 주소에 남기지 않는다 |
| `?dns=off` · `?notify=off` | 시뮬 서버 상태 모의 값(`state.server`) — 「도메인 판단 꺼짐」 배너 / 후속 조치의 「웹훅 미설정」 [10/20] |
| `?as=admin` · `?as=viewer` | 로그인 건너뜀(빠른 확인). 없으면 로그인 화면부터 [10/20 2차] |
| `?auth=fresh` | 첫 로그인부터 — 비밀번호 변경 → 라이선스 → OTP 등록 [10/20 2차] |
| `?notify=fail` · `?discovery=fanotify` | 웹훅 실패 3회(알림 센터 · 서버 설정) / 발견 방식 fanotify(시뮬 기본 docker-events, 실제 백엔드 기본은 auto) [10/20 2차] |
| `?latency=<ms>` · `?fail=audit,installs,scans,events,changes` | 모의 서버 지연(첫 로드 스켈레톤) / 그 조회가 한 번 실패(오류 + 「다시 시도」) [10/20 2차]. `?fail=audit:2` 처럼 `:N` 이면 N 번 실패(인증 감사는 `authAudit`) [10/20 결정 4] |
| `?retry=<ms>` | 목록 오류의 자동 재시도 주기(기본 30초 — 확인용으로 줄인다) [10/20 결정 4] |
| `?license=soon` · `?license=expired` | 라이선스 20일 남음(칩 노랑) / 이틀 전 만료(칩 빨강) [10/20 결정 3] |
| `#/settings?tab=` (server · accounts · license · auth-audit) | 설정 화면 탭(기본 서버 설정). 인증 감사 필터는 주소에 남기지 않는다 [10/21]. 옛 주소 `#/policies?tab=accounts` · `#/policies?settings=1` 은 여기로 보낸다 [10/20 결정 2] |
| `#/audit?…&tab=evidence` | 감사 상세(격리된 행)의 증거 탭 [10/20 2차] |

### 데모 계정 (시뮬레이션 전용 가짜 값 — 실제 비밀번호 아님)

| 아이디 | 역할 | 비밀번호 | 비고 |
| --- | --- | --- | --- |
| `admin` | 관리자 | `demo-pass-1234` | 기본: OTP 등록됨 → OTP 입력 단계. `?auth=fresh` 면 비밀번호 변경부터 |
| `viewer` | 조회자 | `demo-pass-1234` | 쓰기 버튼이 모두 사라진다. `?auth=fresh` 면 「관리자가 먼저 라이선스를 등록해야 합니다」 |

새 비밀번호 규칙: **5자 이상 · 아이디와 다르게 · 확인 칸과 같게** [10/20 결정 변경 — 10자 → 5자]. 짧으면 「비밀번호는 5자 이상이어야 합니다」(화면 검사와 모의 서버가 같은 문구).

모의 단순화: **OTP 는 실제 TOTP 계산 대신 「000000 만 틀림, 그 밖의 6자리는 통과」**, 복구 코드는 `XXXX-XXXX`(헷갈리는 글자 0 O 1 I L 제외) 형식이면 한 번 통과(같은 코드 재사용 거부). 라이선스 키는 숫자 16자리면 1년 평가판(백엔드와 같은 규칙). QR 은 외부 라이브러리 없이 그린 **목업 그림(스캔 불가)** — React 는 qrcode 라이브러리로 `uri` 를 그린다. 5번 연속 틀리면 그 계정은 5분 잠금(문구는 아이디 존재 여부와 상관없이 같다). 세션은 이 탭(sessionStorage)에만 남고, 새로고침하면 모의 서버의 계정 · 사용한 복구 코드는 처음 값으로 돌아간다.

**실제 백엔드 모드**: 인증은 쿠키 세션이라 `fetch(..., { credentials: 'include' })` 로 부른다. **목업과 백엔드를 같은 호스트 이름으로 연다** — 둘 다 `127.0.0.1`(예: 목업 `http://127.0.0.1:8766`, 백엔드 `http://127.0.0.1:8000`). 한쪽을 `localhost` 로 열면 SameSite=Strict 쿠키가 붙지 않아 로그인 뒤에도 401 이 난다. 백엔드 `ALLOWED_ORIGINS` 에 목업 출처를 넣는다. 인증 경로가 없는 옛 백엔드(`/api/auth/me` 404)는 로그인 없이 연다.

## 관련: 설치 샌드박스 (실제 백엔드)

목업은 화면 검토용이다. 실제로 패키지 설치를 감시·격리하는 것은 `tools/sg-install` + `make sandbox-up`(저장소 루트)이다.
목업 정책 화면에는 그 규칙(`sandbox-egress`·`sandbox-secrets`)과 도메인 허용/금지(`allowHosts`/`denyHosts`) 필드가 함께 보인다.

## 데이터 소스 두 가지

| 소스 | 피드·통계 | 정책 | 감사 로그 | 데모 제어 |
| --- | --- | --- | --- | --- |
| **내장 시뮬레이션** (기본) | 백엔드 mock 소스와 같은 컨테이너 3개(`web-api`·`worker`·`pkg-reqeusts`)가 100ms 마다 정상 이벤트를 낸다. 공격 시나리오 1→2→3 은 **지금 실행**으로만(자동 주기 기본 끔 — 데모는 「판정 대기 0」에서 시작). `shared/data.js` 의 `evaluate()` 가 기본 정책 10개(10/30 dns 2개 포함) + 시스템 규칙 `blocklist-hosts` 를 백엔드 엔진과 같은 순서로 평가 | 메모리(모의 서버가 건 · 제안 · 차단 목록 · 변경 이력도 들고 있음) | 시드 고정 약 90건(24h 런타임 경고 + 어제 격리된 설치 2건) + 실시간 위반이 쌓인다 | 전부 동작. **지금 실행**은 격리 중이던 컨테이너를 먼저 재기동(차단 이미지면 기동 즉시 격리)하고 일시정지도 해제한 뒤 바로 흘린다 |
| **실제 백엔드** | `GET /api/events/recent`·`/api/stats` 로 채우고 `/ws/events` 로 실시간 수신 (1s→10s 백오프 재연결) | `GET/POST/PUT/DELETE /api/policies` (쿠키 세션) | `GET /api/audit` (id 커서) | 격리 모드·공격 실행은 백엔드 설정을 따르므로 안내만 뜬다 |

실제 모드는 다른 출처에서 REST 를 부르므로 백엔드 `ALLOWED_ORIGINS` 에 이 페이지의 출처(`http://127.0.0.1:8766`, 파일로 열었으면 `null`)가 있어야 한다.
`make backend` 가 그렇게 띄운다. 연결이 안 되면 상단에 붉은 배너로 이유가 나온다.

### 판정 흐름 (모의 서버 — `shared/app.js` 의 `srv`, Claude Docs 「API 계약」 탭)

- **건 열기**: 설치 세션이 격리 · 경고가 되는 순간 세션당 1건. 런타임은 `sg-install-*` 가 아닌 컨테이너에 격리됨 · 격리 대상이 나오면, 같은 이름으로 열린 건이 없을 때만 새 건(있으면 위반 수만 증가). 경고만으로는 런타임 건을 열지 않는다
- **판정 → 제안 초안**: 악성 = 패키지(설치) 또는 이미지(런타임) 차단 + 위반 통신의 도메인 차단. 오탐 = 걸린 규칙마다 가장 좁은 예외(파일 `allowPaths` · 도메인 있는 통신 `allowHosts` · 도메인 없는 통신 `allowCidrs` IP/32, 실행 규칙은 자동 예외 없음). 이미 판정된 건은 409
- **미리보기**: 제안을 적용한 정책 사본으로 감사 로그를 다시 평가해 탐지 결과가 바뀌는 행만. **적용**: 차단 목록 · 규칙 반영 → 변경 이력 → 제안 applied → 건 closed. **버림**: 변경 없이 건 closed
- **차단이 먹는 곳**: 패키지 = 데모 제어 설치가 `blocklist/check` 후 「설치 전 거부」 · 이미지 = 재기동 즉시 격리(`blocked-image`, 새 건 없음) · 도메인 = 시스템 규칙 `blocklist-hosts`
- 처리자는 로그인 계정의 표시 이름(`UI.actor()`). 조회자의 쓰기는 403

### 토폴로지 설계 (2일차 재설계 — React 에도 이식)

컨테이너 → 프로세스 → 파일/목적지 3열 고정 레이아웃. 위험한 것이 위로 오도록 정렬한다.

- **엣지 위에 글자를 두지 않는다.** 예전엔 `open`/`connect` 라벨이 곡선·화살표와 겹쳤다. 종류는 말단 노드 안의 **kind 칩**(`open` 하늘색 · `connect` 청록)으로, 횟수는 노드 오른쪽 **×N** 으로 보인다.
- 컨테이너 노드 오른쪽에 **상태 칩**(격리됨·격리 대상·경고). 격리 대상은 점선 테두리.
- 위반 엣지는 굵고(2.25px) 점선이 흐른다. 노드에 마우스를 올리면 그 노드의 연결선만 남고 나머지는 흐려진다.
- 노드를 누르면 오른쪽에 **선택한 노드** 카드: 종류·이름·컨테이너·탐지 결과·횟수/위반·마지막 시각·걸린 규칙(정책 화면 링크)·사유·"이벤트에서 보기". 건이 있는 컨테이너를 고르면 노드 카드 대신 **판정 카드**(이미지 · 위반 · 걸린 규칙 · 판정 버튼).
- 오른쪽 **공격 체인** 패널: 컨테이너별로 위반을 일으킨 노드를 데모 시나리오 순서로 나열한다 — **1 실행**(프로세스의 exec 위반) → **2 파일**(open) → **3 통신**(connect). 각 단계에 규칙 id 와 탐지 결과 배지. 누르면 그래프의 해당 노드와 연결선이 강조된다. 설치 검사 시트의 공격 체인과 **같은 부품**(`UI.attackChain`)이다 [10/15 목표].
- 긴 경로는 가운데 말줄임(`/usr/loc…usts/__init__.py`), 전체는 툴팁.

2차 반영(2026-10-15, 사용자 목표 · 판정 흐름 — Claude Docs 「사용자 목표」 · 「API 계약」 탭):
- **탭 하나 = 질문 하나** — 각 탭이 한 질문에만 답하게 정리(위 화면 표). 같은 정보는 한 탭에만
- **대시보드** — 첫 줄 「판정 대기 N」 목록(설치 · 런타임 함께, 0건이면 「처리할 일 없음」) + 오늘 요약 + 작은 「감시 중」 분당 위반 막대 카드
- **판정 흐름** — 「확인함」 대신 판정 2버튼 「악성 확정」 / 「오탐」 → 제안 초안 → 정책 맨 위 「제안된 변경」에서 미리보기(감사 로그 재평가 · 다음 설치 · 기동부터) → 적용 / 버림 → 건 종결 + 변경 이력. 처리자 「보안 담당자」 (`decide` · `proposals` · `preview` · `apply` · `discard`)
