# SupplyGuard — 프론트엔드 목업

정적 HTML · 바닐라 JS · 외부 라이브러리 없음. React 대시보드(`frontend/`)와 같은 데이터 스키마 · 디자인 토큰을 쓴다.
**React 가 기준이고 목업은 결정 확인용이다** [2026-10-15]. 화면 변경은 목업에서 먼저 보이고 확정한 뒤 React 에 옮긴다.
두 시나리오(설치 검사 · 런타임 감시)를 같은 비중으로 다룬다.

## 열기

| 방법 | 명령 |
| --- | --- |
| 파일로 바로 | `mock/index.html` 을 브라우저로 연다 (file:// 로 동작) |

## 관련: 설치 샌드박스 (실제 백엔드)

목업은 화면 검토용이다. 실제로 패키지 설치를 감시·격리하는 것은 `tools/sg-install` + `make sandbox-up`(저장소 루트)이다.
목업 정책 화면에는 그 규칙(`sandbox-egress`·`sandbox-secrets`)과 도메인 허용/금지(`allowHosts`/`denyHosts`) 필드가 함께 보인다.

## 데이터 소스 두 가지

| 소스 | 피드·통계 | 정책 | 감사 로그 | 데모 제어 |
| --- | --- | --- | --- | --- |
| **내장 시뮬레이션** (기본) | 백엔드 mock 소스와 같은 컨테이너 3개(`web-api`·`worker`·`pkg-reqeusts`)가 100ms 마다 정상 이벤트를 낸다. 공격 시나리오 1→2→3 은 **지금 실행**으로만(자동 주기 기본 끔 — 데모는 「판정 대기 0」에서 시작). `shared/data.js` 의 `evaluate()` 가 기본 정책 7개 + 시스템 규칙 `blocklist-hosts` 를 백엔드 엔진과 같은 순서로 평가 | 메모리(모의 서버가 건 · 제안 · 차단 목록 · 변경 이력도 들고 있음) | 시드 고정 약 90건(24h 런타임 경고 + 어제 격리된 설치 2건) + 실시간 위반이 쌓인다 | 전부 동작. **지금 실행**은 격리 중이던 컨테이너를 먼저 재기동(차단 이미지면 기동 즉시 격리)하고 일시정지도 해제한 뒤 바로 흘린다 |
| **실제 백엔드** | `GET /api/events/recent`·`/api/stats` 로 채우고 `/ws/events` 로 실시간 수신 (1s→10s 백오프 재연결) | `GET/POST/PUT/DELETE /api/policies` (Bearer 토큰) | `GET /api/audit` (id 커서) | 격리 모드·공격 실행은 백엔드 설정을 따르므로 안내만 뜬다 |

실제 모드는 다른 출처에서 REST 를 부르므로 백엔드 `ALLOWED_ORIGINS` 에 이 페이지의 출처(`http://127.0.0.1:8766`, 파일로 열었으면 `null`)가 있어야 한다.
`make backend` 가 그렇게 띄운다. 연결이 안 되면 상단에 붉은 배너로 이유가 나온다.

## 화면

사이드바는 시나리오별 묶음이다: 대시보드 / **설치 검사** / **런타임 감시**(이벤트 · 토폴로지) / **설정 · 기록**(정책 · 감사 로그). 상단에는 화면 이름과 그 화면의 주 버튼 · 입력이 있다.

### 판정 흐름 (모의 서버 — `shared/app.js` 의 `srv`, Claude Docs 「API 계약」 탭)

- **건 열기**: 설치 세션이 격리 · 경고가 되는 순간 세션당 1건. 런타임은 `sg-install-*` 가 아닌 컨테이너에 격리됨 · 격리 대상이 나오면, 같은 이름으로 열린 건이 없을 때만 새 건(있으면 위반 수만 증가). 경고만으로는 런타임 건을 열지 않는다
- **판정 → 제안 초안**: 악성 = 패키지(설치) 또는 이미지(런타임) 차단 + 위반 통신의 도메인 차단. 오탐 = 걸린 규칙마다 가장 좁은 예외(파일 `allowPaths` · 도메인 있는 통신 `allowHosts` · 도메인 없는 통신 `allowCidrs` IP/32, 실행 규칙은 자동 예외 없음). 이미 판정된 건은 409
- **미리보기**: 제안을 적용한 정책 사본으로 감사 로그를 다시 평가해 탐지 결과가 바뀌는 행만. **적용**: 차단 목록 · 규칙 반영 → 변경 이력 → 제안 applied → 건 closed. **버림**: 변경 없이 건 closed
- **차단이 먹는 곳**: 패키지 = 데모 제어 설치가 `blocklist/check` 후 「설치 전 거부」 · 이미지 = 재기동 즉시 격리(`blocked-image`, 새 건 없음) · 도메인 = 시스템 규칙 `blocklist-hosts`
- 처리자는 데모 계정 「보안 담당자」 하나. 목업 sim 은 mock 소스라 판정 · 적용에 토큰이 필요 없다(계약: `EVENT_SOURCE=mock` 이면 토큰 없이)

### 토폴로지 설계 (2일차 재설계 — React 에도 이식)

컨테이너 → 프로세스 → 파일/목적지 3열 고정 레이아웃. 위험한 것이 위로 오도록 정렬한다.

- **엣지 위에 글자를 두지 않는다.** 예전엔 `open`/`connect` 라벨이 곡선·화살표와 겹쳤다. 종류는 말단 노드 안의 **kind 칩**(`open` 하늘색 · `connect` 청록)으로, 횟수는 노드 오른쪽 **×N** 으로 보인다.
- 컨테이너 노드 오른쪽에 **상태 칩**(격리됨·격리 대상·경고). 격리 대상은 점선 테두리.
- 위반 엣지는 굵고(2.25px) 점선이 흐른다. 노드에 마우스를 올리면 그 노드의 연결선만 남고 나머지는 흐려진다.
- 노드를 누르면 오른쪽에 **선택한 노드** 카드: 종류·이름·컨테이너·탐지 결과·횟수/위반·마지막 시각·걸린 규칙(정책 화면 링크)·사유·"이벤트에서 보기". 건이 있는 컨테이너를 고르면 노드 카드 대신 **판정 카드**(이미지 · 위반 · 걸린 규칙 · 판정 버튼).
- 오른쪽 **공격 체인** 패널: 컨테이너별로 위반을 일으킨 노드를 데모 시나리오 순서로 나열한다 — **1 실행**(프로세스의 exec 위반) → **2 파일**(open) → **3 통신**(connect). 각 단계에 규칙 id 와 탐지 결과 배지. 누르면 그래프의 해당 노드와 연결선이 강조된다. 설치 검사 시트의 공격 체인과 **같은 부품**(`UI.attackChain`)이다 [10/15 목표].
- 긴 경로는 가운데 말줄임(`/usr/loc…usts/__init__.py`), 전체는 툴팁.
