# 탐지 시나리오와 DB 조사 흐름

대시보드의 **시나리오 열기** 또는 **탐지 시나리오** 메뉴에서 시작합니다. 이 기능은 외부 대상에 공격 패킷을 보내지 않습니다. 문서용 주소 `192.0.2.10 → 198.51.100.20`의 합성 피처를 실제 탐지 엔진으로 보내고, 결과를 운영 PostgreSQL에 `SIMULATION` 출처로 저장합니다.

## 발표 시연: 침입 탐지 리허설

1. HTTPS 또는 SSH 터널의 `http://127.0.0.1:18080/#scenarios`를 엽니다. 관리자 토큰을 입력하고 **침입 탐지 리허설 실행**을 누릅니다.
2. 15초 동안 정상 → 포트 탐색 → SYN 폭주 → 대량 전송 → 회복을 관찰합니다. 단계마다 3개 샘플을 저장합니다.
3. 패킷/s와 Mbps 그래프, 단계별 진행 상태, 기대 유형과 실제 탐지 결과를 비교합니다. 기본 규칙에서는 15개 샘플·9개 이벤트를 기대합니다. 운영 설정에 따라 결과가 다를 수 있으며 임계값을 자동 변경하지 않습니다.
4. **탐지 이벤트에서 보기**로 이동합니다. 같은 실행 ID에 해당하는 DB 이벤트, 심각도 집계, 분당 탐지 그래프가 표시됩니다.
5. 이벤트를 열어 원본 피처와 기대 유형을 확인하고 **정탐 확인**, 검토 메모, 관리자 토큰을 입력해 저장합니다.
6. 검토 상태 필터로 확인하고 페이지를 새로고침합니다. 기록·검토·그래프가 유지됩니다. 이벤트 상세의 **실행 그래프** 링크로 다시 돌아갈 수 있습니다.

| 단계 | 모의 입력 | 기본 규칙의 기대 결과 |
|---|---|---|
| 정상 접속 | 35 pps, 28,000 bytes/s | 정상 통과 |
| 포트 탐색 | 10초 고유 포트 48개, 80 pps | PORT_SCAN · high |
| SYN 폭주 | 출발지 4,800 pps 중 SYN 4,700/s | SYN_FLOOD · critical |
| 대량 전송 | 약 13.5 MB/s, 9,500 pps | LARGE_FLOW · medium |
| 회복 | 정상 입력으로 복귀 | 정상 통과 |

SYN Flood, Port Scan, 대량 전송 단독 시나리오는 각각 9초입니다. 동시 실행은 하나로 제한하고, 요청 UUID를 재사용하면 같은 실행을 반환합니다. 중지 요청은 관리자 인증이 필요합니다. 서버 재시작으로 남은 running 기록은 interrupted로 표시하며 자동 재실행하지 않습니다. 이 상태 관리를 위해 현재 백엔드는 worker 1개로 실행합니다.

## 데이터와 해석

- `scenario_runs`: 실행 ID·종류·상태·시작/종료·당시 임계값·엔진 모드.
- `scenario_samples`: 단계·시각·전체 피처·기대 유형·실제 탐지·점수·이벤트 FK. 이벤트와 샘플은 한 트랜잭션으로 저장한 뒤 WebSocket을 보냅니다.
- `detection_events`: 기존 이벤트에 출처·실행 FK·기대 유형·검토 시각을 추가합니다. 기존 데이터는 `live`로 유지합니다.
- 실시간 대시보드의 패킷·대역폭 그래프는 Collector 데이터만 집계합니다. 시나리오 그래프는 저장된 모의 샘플을 사용합니다. 이벤트 페이지는 출처별로 분리 조회할 수 있습니다.
- 시나리오는 실제 규칙/모델을 호출하지만 커널 XDP, 패킷 캡처, Collector 전송 경로를 검증하지 않습니다. 해당 계층 검증은 기존 격리망 `infra/lab_e2e.py`를 사용합니다.
- 기대 유형 일치는 설계된 합성 샘플의 비교 결과이며 PCAP F1, 실제 공격 성공률 또는 보안 보증이 아닙니다. 분석가 판정도 CIC 정답이나 학습 데이터에 자동 반영하지 않습니다.
- 토큰은 브라우저 메모리에만 존재하며 요청 후 입력을 지웁니다. 모의 실행은 Slack을 호출하지 않습니다.

## API

| 요청 | 기능 | 인증 |
|---|---|---|
| `GET /api/scenarios` | 시나리오 목록 | 조회 |
| `GET /api/scenarios/runs` | 최근 실행 목록 (기본 20, 최대 100) | 조회 |
| `POST /api/scenarios/runs` | `{scenario_id, request_id}` 실행 | 관리자 Bearer |
| `GET /api/scenarios/runs/{id}` | 단계별 샘플·집계·임계값 | 조회 |
| `POST /api/scenarios/runs/{id}/stop` | 실행 중지 | 관리자 Bearer |
| `GET /api/events/summary` | 현재 조건 전체 집계·최근 24시간 분당 집계 | 조회 |
| `PATCH /api/events/{id}/review` | `{is_confirmed: true/false/null, note}` | 관리자 Bearer |

이벤트 목록과 summary는 `source`, `scenario_run_id`, `review`, `severity`, `attack_type`, `ip`, `start_time`, `end_time` 필터를 공유합니다. 타임라인만 최근 24시간으로 제한되며 총계·분포는 전체 검색 범위입니다. 메모는 최대 2,000자입니다.
